## 结论及证据范围

GeoGeek Lab 的差异化定位是**通过交互揭示空间观测的条件、尺度、模型和限制**，而不是展示任意地图特效。Collection → Record → Instrument 的信息分层，以及 Water as Spectrum 的科学来源与限制说明，都应保留。

本审查阅读了公开页面的可检索结构及 GitHub 仓库源码。当前执行环境**不能直接操纵线上浏览器，也没有实际获得桌面/移动端渲染截图、录屏、Lighthouse 或屏幕阅读器结果**。因此，下表的问题按「源码已确认」和「运行时待验证」分类。任何获奖等级结论必须以真实设备、真实用户和性能数据为依据。

## 推荐的完整体验逻辑

```text
COLLECTION / 扫描与选择
          │
          ▼
RECORD / 明确来源、前提、限制
          │
          ▼
INSTRUMENT / 选择观察任务
          │
          ▼
改变一个条件 ──→ 立即观察变化
          │                 │
          └── 解释、比较和记录 ←─┘
          │
          ▼
导出结果 / 返回 Lab，并恢复选择位置
```

**交互原则：** 让用户先看到「可以发现什么」，再展开「可以调整什么」，最后显示「这个发现的科学边界」。不要把对照图、参数表与高级推断全部挤进默认视图。

## 品牌级设计系统目标

- **色彩**：深绿背景、灰白数据前景、珊瑚/赭色操作信号。科学状态不能只用颜色编码。
- **字级**：工作区主标题优先；工作区任务次之；控件与模型状态保持可读；真正的仪器编号与版本号才使用微型字体。
- **空间**：正文和图表使用一致的内边距系统。图表是信息视觉中心，不让上方工具与旁边参数栏争夺注意力。
- **动作**：只有因操作发生的模型变化才使用动画。不要把连续变化伪装为真实观测。
- **来源**：内部模拟、真实遥感观测、模型基准和外部验证必须保持明确区分。

## 本轮实际改动

1. `instrument.js` 增加宿主加载状态，预备工作区建立、出错回退和取消时都可正确清除。
2. `instrument.css` 增加独立加载视觉和 Reduced Motion 规则。
3. `v102-quality.css` 优化导航保持、触控目标、状态标签和图表注释对比度。
4. `app/index.html` 在科学视图样式之后加载品质修正层。
5. `core/modules.js`、`lab.html` 更新版本引用，防止旧 JavaScript 缓存继续使用。
6. `tests/water/workbench-v102-quality.test.mjs` 增加源码契约测试。

以上只是一轮**可靠性与交互可用性修补**，不是完成整个 Lab 的奖项级重设计。本轮不修改水色遥感科学模型、数值方法或数据含义。

## 三轮改进闭环

- **第 1 轮：可信启动与基础可用性**。完成宿主加载状态、导航与触控基础；运行静态契约测试。
- **第 2 轮：叙事与操作效率**。观察 5 名用户如何进入九个工作区，减少首屏决策成本，设计一条「改变参数→即时响应→科学解释」的主路径。
- **第 3 轮：视觉精修与全设备发布**。对桌面/移动视口、状态动画、性能和 WCAG 执行可复现测试；直至阻断性缺陷关闭。
