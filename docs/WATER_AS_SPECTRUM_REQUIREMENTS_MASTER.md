# Water as Spectrum：多版本功能需求与科学软件主规格（母本）

> **文件性质**：产品需求文档（PRD）＋科学模型契约（Scientific Contract）＋技术实现边界＋测试追踪矩阵＋版本治理规则。  
> **管理对象**：GeoGeek Lab `lab:l13` / `instrument=water`。  
> **当前基线**：V9.1。**规划版本**：V10.0、V10.1、V10.2、V10.3，以及未来增量版本。  
> **文档状态**：`PROPOSED`。科学负责人、开发负责人审批后改为 `APPROVED`。**本文件不是已完成开发或已通过验证的声明**。

## 0. 文档使用说明与维护规则

### 0.1 本文档如何使用

1. 任何新需求先登记为 `Fxx-Ryyy`，不得直接以界面想法代替需求。
2. 每项需求必须同时给出模型前提、用户可见行为、输入/输出、异常状态及验收测试。
3. 每个开发版本只从母本挑选已批准的需求形成版本范围；未纳入版本的需求保持开放。
4. 任何科学公式、波长有效域、数据源、误差解释发生变化时，必须更新科学契约并补充测试。
5. 每次发布附带变更记录、数据/模型版本清单、验收记录和已知限制。
6. 本文档保留稳定需求编号；不因移动章节、调整优先级或变更版本而重新编号。

**变更权威顺序**：已批准的科学契约与测量定义 → 已批准的本母本需求 → 对应版本的发布范围（Release Scope）→ 架构决策记录（ADR）→ 代码与测试。若存在冲突，暂停受影响需求，先发布决策记录。旧版 `WATER_AS_SPECTRUM_SCIENTIFIC_CONTRACT.md` 是 V1 科学基线，不因本文件发布而自动失效；V10 的定义变化必须建立显式的兼容关系。

### 1.3 V9 科学基线（必须保护）

- 半解析水体光谱：`400–700 nm`，`1 nm` 采样，共 301 点。
- 基线海水条件：20°C、35 PSU；并非任意盐度/温度场景。
- 水体五参数：`chl`、`ag440`、`aNap443`、`bbp443`、`eta`。
- 水体映射：`a = aw + aph + ag + aNAP`；`bb = bbw + bbp`；`u = bb/(a+bb)`；`rrs = 0.0949u + 0.0794u²`；`Rrs = 0.52rrs/(1 − 1.7rrs)`。
- 固定组分光谱斜率基线：CDOM `0.0176 nm⁻¹`，NAP `0.0123 nm⁻¹`。
- 大气正演为近似量 `rho_TOA*`，不能标注为真实卫星 L1 TOA 观测。
- V9 实验 JSON 已到 `schemaVersion: 6`；原有 3/4/5 兼容导入。
- V9 不确定性：局部有限差分；假设 `Σ = σ²I`；满秩时才输出形式协方差。
- 既有 SRF 数据有来源及其局限；其二次来源不等于已认证的 ESA/USGS 原始产品版本。

### 1.4 问题陈述

V9 主要回答“水体组分如何影响 IOP，再如何近似影响光谱”。V10 应进一步回答：

1. 光在水下沿深度和方向如何传播？
2. 半解析模型与独立辐射传输解在何种条件下接近或偏离？
3. 大气路径、仪器响应与校正过程如何改变可观测量？
4. 参数何时可辨识，何时仅有条件上的局部信息？
5. 模拟结果与实测数据的差异及不确定性究竟来自哪里？

### 1.5 产品目标与明确非目标

**必须实现的目标**：教学解释清楚、不同模型可对照、证据和有效域可追踪、结果可导出并重新计算、版本间保持科学语义一致。

**本轮非目标**：声称替代 Hydrolight、SeaDAS、ACOLITE 或业务处理系统；承诺全球全部水型预测准确；对未验证近红外光谱提供数值；把示意粒子动画作为 Monte Carlo 光子路径；把算法数值闭合当作独立真实性验证；直接在线完成所有波长/角度/深度/组分的通用多次散射 RT 求解。

### 1.6 核心用户与用户故事

| 用户 | 主要问题 | 成功标志 |
|---|---|---|
| 本科生 | `a`、`bb` 与 `Rrs` 为什么关联？ | 能用单次参数扰动解释光谱变化及模型限制 |
| 研究生 | 几何、深度、相函数如何改变光场？ | 能对照 RT 参考解并解释偏差 |

## 2. 科学软件强制契约（SC）

任何功能开发均不得违反本节。这些条目高于界面与性能偏好。

| 编号 | 不可违反的规则 | 常见失败模式 |
|---|---|---|
| SC-01 | 明确区分 IOP、AOP、辐亮度、辐照度、无量纲反射率 | 把 `Rrs` 写成无量纲或把 `bb` 称为总散射 |
| SC-02 | `Rrs = Lw(0+)/Ed(0+)`；`rrs = Lu(0−)/Ed(0−)`，单位 `sr⁻¹` | 上下水体量混用 |
| SC-03 | `b`、`bb` 和体积散射函数 `β` 必须满足积分一致性 | 用 `bb` 直接替代总散射 `b` |
| SC-04 | 半解析公式是近似，不得宣传为完整角度—深度辐射传输求解 | 仅更换图形就标记为 RT solver |
| SC-05 | 明确区分连续单色谱、传感器积分量、实际仪器观测 | 用中心波长值冒充真实波段结果 |
| SC-06 | 每个数值携带来源、有效域、单位、质量状态和模型版本 | 无效域返回貌似可信的数字 |
| SC-07 | 正演与反演使用同一模型所得自闭合，仅用于一致性检查 | 把逆犯罪结果当作独立检验 |
| SC-08 | 数值满秩 ≠ 全局唯一；形式协方差 ≠ 真实检索精度 | 满秩后显示“反演可靠” |
| SC-09 | 观测误差、模型误差、参数先验必须分开展示和记录 | 将假定 `σ` 说成真实卫星噪声 |
| SC-10 | 参考 RT 解必须有独立来源/求解过程，并记录输入与求解设置 | 将 V9 光谱改名为“参考解” |
| SC-11 | 无 SRF、部分覆盖、物理范围外必须显式缺测/提示 | 静默补零、裁切或臆造传感器曲线 |
| SC-12 | 缺少荧光、拉曼散射、底反射等时不得从演示中暗示已求解 | 高斯峰被标为经验证的叶绿素荧光 |
| SC-13 | 物理光场图与概念动画必须标明数据驱动/仅示意 | 动画角度与数值辐亮度不一致 |
| SC-14 | 每次改变物理公式或查表源必须改变科学模型/数据版本标识 | 仅更新前端版本，旧导出被静默重解释 |
| SC-15 | 比较不同模型时，必须对齐相同的物理输入、波长、几何及边界条件 | 条件不一致却绘制“模型误差” |
| SC-16 | 输出不确定性、误差或验证得分时，必须指出统计对象、样本、权重、量纲和前提 | 把随机误差、偏差与 RMSE 混为一谈 |

### 2.1 RT 物理定义

建议水体稳态单色传输符号为：

```text
μ ∂L(z, Ω, λ)/∂z = -[a(λ)+b(λ)] L(z, Ω, λ)
                   + ∫₄π β(Ω′→Ω, λ) L(z, Ω′, λ) dΩ′
                   + S(z, Ω, λ)
```

此式中的 `z` 正方向、`μ` 正负和边界入射方向必须在选定求解器规范中统一；本式是结构约束而非可直接复制的离散实现。必须记录：

- `b(λ) = ∫₄π β(Ω′→Ω,λ) dΩ`，适用所采用的相函数归一化约定。
- `bb(λ)` 为后向半球积分，后向半球如何以散射角定义必须写入数据契约。
- `Ed(z,λ)`、`Eu(z,λ)` 以相应半球辐亮度加权积分计算，`Lu` 为方向辐亮度或明确的有限立体角平均量。
- 允许用离线 LUT 表示参考 RT；LUT 结果仍须指出来自哪个求解器及其数值设置。
- “深度坐标”不等于“底部水深”。首批采用光学深水假设，绝不从 20 m 深度剖面暗示存在 20 m 底部。

### 2.2 TOA 与传感器量定义

保留 V9 的 `rho_TOA*` 作为**教学近似量**。实际传感器辐亮度与反射率应记录约定、太阳天顶角、地日距离修正及辐照度定义。

对于辐亮度型传感器，需首先进行波段辐亮度积分：

```text
L_band = ∫ S(λ) L_TOA(λ) dλ / ∫ S(λ) dλ
```

若使用带内等效太阳辐照度计算反射率，必须按适用仪器和产品规范构造，而非把 `∫S ρ(λ)/∫S` 在所有情景直接当作实际反射率观测。**该要求是测量定义修正，不能据此推断 V9 的教学带平均本身编程错误。**

### 2.3 误差与反演定义

- 线性化 Jacobian：`J_ij = ∂y_i/∂p_j`；明确物理单位与参数归一化尺度。
- 观测噪声协方差：`Σ_obs`；必须标注假设分布、相关性、波段适用性和来源。
- 条件 Fisher：`F = Jᵀ Σ_obs⁻¹ J`；满秩是局部结论。
- 逆问题结构误差：不能以 `Σ_obs` 单独替代；应另建偏差、模型差异及先验敏感性诊断。
- 若统计模型不符合高斯/线性假设，应明确把 `F⁻¹` 标为条件近似而非校准过的区间。

## 3. V10 产品信息架构与通用交互

### 3.1 三个顶层任务模式

```text
Water as Spectrum V10
│
├── LEARN（指导式实验）
│   ├── 组分—IOP—AOP
│   ├── 水下深度与角度光场
│   ├── 大气校正误差
│   └── 多波段可辨识性
│
├── EXPLORE（自由探索）
│   ├── 原 V9 八个工作区
│   └── 新 WATER RT 工作区
│
└── VALIDATE（模型与观测验证）
    ├── SEMI-ANALYTICAL vs RT
    ├── BENCHMARK CASES
    ├── FIELD MATCHUP
    └── REPORT & PROVENANCE
```

不应把用户的每个科学问题都变成一枚顶层标签。LEARN/EXPLORE/VALIDATE 是交互任务入口；底层共享同一实验状态和模型结果，避免出现三套物理公式。

### 3.2 统一工作区骨架

```text
┌───────────────────────────────────────────────────────┐
│ 课题 / 当前模型 / 有效域 / 数据可信度 / 来源详情          │
├────────────────────────────────┬──────────────────────┤
│ 物理示意或数据驱动场景         │ 参数、几何及模型切换   │
│ 深度/角度/光谱上下文            │ 误差与运行条件         │
├────────────────────────────────┴──────────────────────┤
│ 同轴光谱 + 残差 / 深度曲线 + 角度分布 + 数值探针          │
├───────────────────────────────────────────────────────┤
│ 提问 → 预测 → 运行 → 解释 → 检查限制 → 保存/导出          │
└───────────────────────────────────────────────────────┘
```

### 3.3 全局状态协议

所有工作区至少共享：`waterState`、`geometry`、`modelSelection`、`wavelengthSelection`、`sensorSelection`、`noiseScenario`、`experimentId`、`dataProvenance`、`qualityFlags`。切换工作区只应改变视图，不应无提示重置物理状态。发生不兼容组合时，给出明确的“为何不可计算”和恢复选项。

## 5. 功能详细规格：F01–F06

### F01｜科学模型契约、有效域与可信度标识

**用户问题**：当前数字究竟由哪个模型算出？哪些物理过程被忽略？在什么条件下允许引用？

**预期行为**：所有科学图表都有可展开的“MODEL / ASSUMPTIONS / VALIDITY”；显示模型级别 `SEMI_ANALYTICAL`、`REFERENCE_RT`、`OBSERVATION` 或 `ILLUSTRATION`。标记是结果字段，不依赖开发人员手工写在图标题里。

| 原子需求 | 必须实现的行为 | 不得出现的行为 |
|---|---|---|
| F01-R001 | 定义统一变量字典：符号、英文名、中文名、单位、上下水面、波长/方向约定 | `Rrs` 与 `rho` 混名 |
| F01-R002 | 计算结果带 `modelId/modelVersion/dataVersion/assumptions` | 结果只显示应用 UI 版本 |
| F01-R003 | 有效性状态 `valid/partial/out_of_domain/missing_data/failed/not_applicable` | 无效状态变成数值零 |
| F01-R004 | 图表悬浮、图例、CSV、JSON 均保留质量状态及原因 | 导出后失去警告 |
| F01-R005 | “物理链路”中明确区分计算模块与仅示意模块 | 假动画产生计算级可信错觉 |
| F01-R006 | 用户可从图表查看输入参数、模型公式摘要和来源 | 模型逻辑成为黑箱 |
| F01-R007 | 新模型/新数据加入前须通过科学契约检查清单 | 先显示再补有效域说明 |

**输入**：模型计算元数据、当前状态、数据源 manifest、模型域断言。  
**输出**：全工作区一致的 provenance 面板、数值有效性标志、可追踪的导出元信息。  
**异常**：模型版本缺失、未确定单位、没有可信来源的参考解时，禁止标记为 `validated`。对旧状态缺字段可以迁移为 `legacy_unknown`，不得伪造来源。

**验收**：

- `AT-F01-01`：切换 V9 半解析与新参考解，每张相关图的模型身份即时且正确更新。
- `AT-F01-02`：请求 720 nm 的旧 V9 水体谱时，得到 `out_of_domain`，不生成表观有效的数值。
- `AT-F01-03`：导出结果再导入，模型身份、单位、异常状态及缺失原因完整保留。
- `AT-F01-04`：在仅示意动画页面，不出现“求解光子路径”等误导性描述。

**完成定义（DoD）**：统一模型契约在至少 WATER OPTICS、SENSOR、UNCERTAINTY 中接入；科学负责人审核字段语义；跨功能测试通过。

### F02｜水体 IOP 参数化与情景管理

**用户问题**：光谱变化来自一个独立参数的数学扰动，还是来自真实水体中可能相关的一组变化？

**预期行为**：在保留 V9 `chl/ag440/aNap443/bbp443/eta` 基线的前提下，加入参数化模型选择与物理假设切换。**默认实验与 V9 兼容**；任何新参数化显式切换到新的模型 ID。

| 原子需求 | 必须实现的行为 |
|---|---|
| F02-R001 | 完整保留 V9 五参数基线输出、有效域和基准状态。 |
| F02-R002 | `Sg` 与 `SNAP` 新增“文献基线固定/自定义”模式；自定义范围需有文献或教学来源，不把范围称为自然极值。 |
| F02-R003 | 组分图同时显示 `aw, aph, ag, aNAP, total a, bbw, bbp, total bb`，不得把 `bb` 标为 `b`。 |
| F02-R004 | 新增“独立扰动/受约束情景”切换；受约束情景须明确协变参数、训练域或文献假设。 |
| F02-R005 | 增加候选颗粒谱形的模型接口，至少支持既有幂律与一种有出处的替代方案；未验收前标记 `experimental`。 |
| F02-R006 | 温度/盐度控制仅在水体基线系数有效范围内启用；不允许对缺数据区间任意外推。 |
| F02-R007 | 保存模型选项、变动参数和每项参数化来源；比较时提示两个情景的模型是否一致。 |

**设计限定**：增加相函数控制应由 F04 的完整 IOP 状态管理，不得直接从 `bbp443, eta` 唯一反推自然颗粒相函数。生态协变情景属于模型假设，不得标记为“真实藻华模拟”。

**首发切分**：V10.0 完成 R001、R002、R003、R007；V10.2 处理 R004–R006 的已选、可验证方案。

**验收**：

- `AT-F02-01`：默认配置对 V9 黄金谱在明示容差内一致。
- `AT-F02-02`：修改 CDOM 斜率只影响预期组分，且指数谱形与定义一致。
- `AT-F02-03`：切换协变情景时显示协变规则及来源，导出可复现。
- `AT-F02-04`：物理无效参数或不支持的温盐范围被拒绝，显示可操作提示。

**依赖/风险**：F01、数据文献审查；变更 IOP 拟合关系会影响所有下游测试，须标记破坏性科学模型变更。

### F03｜传感器 SRF、波段观测与反演输入一致性

**用户问题**：某个波段究竟是中心波长取值、理想矩形积分、公开测量 SRF 积分，还是实际卫星数据？

**预期行为**：传感器面板始终显示 `sensor/platform/band/responseMode/responseSource/coverage/status`。谱线与波段积分是不同的数据对象。

| 原子需求 | 必须实现的行为 |
|---|---|
| F03-R001 | 为每个波段记录中心、名义宽度、响应支持域、来源/版本/校验和。 |
| F03-R002 | 区分 `nominal_top_hat`、`published_measured`、`official_verified`、`unavailable`；实测二次来源不自动升级为官方认证。 |
| F03-R003 | 建立 `full/partial/unavailable/out_of_model_domain` 四类传感器支持状态，返回覆盖比例和缺失原因。 |
| F03-R004 | 保留 V9 旧模式的连续反射率教学积分；新增物理一致的 `L_TOA → L_band → 适用反射率定义` 数据路径。 |
| F03-R005 | OC4/其他波段算法可明确选择“中心波长教学模式”或“传感器实际波段模式”，输出不能混名。 |
| F03-R006 | 实测 SRF 严格按来源支持区间积分；不静默用高斯或名义矩形代替缺失 SRF。 |
| F03-R007 | 传感器切换保持水体状态不变；无法比较时显示差异条件。 |
| F03-R008 | 当未来取得官方 OLCI/OCI SRF 数据时，保留其版本、探测器/像元适用性、许可与处理历史。 |

**特别约束**：OCI 的光谱采样间隔与光谱响应带宽不是一个概念；图例必须分开说明。近红外波段可以展示官方传感器信息，但若水体模型无域支持，不得生成假的水体 `Rrs`。

**验收**：

- `AT-F03-01`：使用常数辐亮度谱时，归一化 SRF 带平均等于该常数（数值积分容差内）。
- `AT-F03-02`：零/缺失响应函数不能产生有效观测值，导出包含原因。
- `AT-F03-03`：一条复杂光谱的中心取值、矩形积分、实测 SRF 积分以三种独立名称同时展示。
- `AT-F03-04`：OC4 结果记录算法系数版本、用到的 band ID、响应模式和输入变量单位。
- `AT-F03-05`：在未支持 708.75 nm 的半解析模型下，相关 OLCI 波段明示 `out_of_model_domain`。

**风险**：官方响应曲线许可、版本、探测器变化以及归一化约定必须经审核；“实测 SRF”不等于“现场校准后的 L1 观测”。

### F04｜WATER RT：水下辐射传输参考实验

**用户问题**：光场在水下如何随深度、方向、组分与散射相函数变化？

**目标边界**：首版不是通用即时 RT 求解器。采用**独立离线 RT 参考解 + 浏览器数据切片/受限插值**。任何快路径代理模型都须通过独立误差验证。参考解的真实性来自可追溯求解器/实验，而不是界面标签。

| 原子需求 | 必须实现的行为 |
|---|---|
| F04-R001 | 提供统一 RT 输入模型：`λ, a(λ), b(λ), β或归一化P, 几何, 表面边界, 深度坐标, 光源设置`。 |
| F04-R002 | 至少提供清澈、富藻、颗粒丰富三类可追溯参考场景；明确情景数值仅适用于已计算域。 |
| F04-R003 | 输出 `L(z,Ω,λ)` 或经声明的角度采样近似；派生 `Ed, Eu, Lu, Kd`，逐项标注定义。 |
| F04-R004 | 深度轴显示水面位置及 `z` 方向；光学深水状态不展示虚构底部反射。 |
| F04-R005 | 提供太阳天顶角、观察角、散射相函数至少两类可比较设置；仅开放已提供参考数据的组合。 |
| F04-R006 | 显示角度热力图/极坐标、深度剖面、光谱曲线和跨图共享探针。 |
| F04-R007 | 对离散网格提供明确的插值方式、适用域、插值误差估计；不支持时显示不可计算。 |
| F04-R008 | 参考数据 manifest 记录求解器、版本、输入、离散网格、容差、生成脚本、创建日期、哈希和许可。 |
| F04-R009 | 物理示意动画以 `illustrative` 显示；仅真实由光场数据驱动的数值层可以标记 `RT-derived`。 |
| F04-R010 | 支持下载当前剖面/角度切片的科学数据和元数据。 |

**参考数据的最低覆盖建议**：先计算固定三种水型，每种至少选两个入射几何和两类相函数，深度由参考求解器确定可用离散层；不承诺自由连续高维扫描。水型、角度、波长数量须在 ADR 决定后冻结，避免算例成本无限增长。

**物理与求解器验收**：

- `AT-F04-01`：核对 `∫P dΩ` 归一化、`b/β` 积分及 `bb` 后向积分一致性。
- `AT-F04-02`：参考求解的非负辐亮度、边界条件、能量关系在定义的物理/数值容差内通过。
- `AT-F04-03`：至少两套角度和深度分辨率的收敛测试，收敛误差记录在 manifest。
- `AT-F04-04`：浏览器加载指定标准案例，光谱、剖面与原始 reference 文件在数值容差内一致。
- `AT-F04-05`：请求未覆盖的波长/参数或跨越禁止插值边界，显示 `out_of_domain`，不执行隐式外推。
- `AT-F04-06`：深度变化不会被错误解释为浅海水深变化；图中不存在未建模底部信号。

**发布门槛**：没有真正独立参考解和物理核验，不得将功能命名为 `WATER RT` 正式版；允许作为明确标记的 `RT preview / illustrative` 内测版。

### F05｜半解析模型—参考 RT 模型同条件对照

**用户问题**：半解析近似的适用范围是什么？差异来自模型误差，还是输入不一致？

| 原子需求 | 必须实现的行为 |
|---|---|
| F05-R001 | 同步输入水体 IOP、几何和海气界面条件；不相容参数组合禁止直接误差比较。 |
| F05-R002 | 统一比较变量：至少 `Rrs(λ)`；扩展 `rrs, Lu, Ed` 前需确认两个模型都定义相同物理量。 |
| F05-R003 | 支持叠加曲线、绝对残差 `Δ = approximate − reference`、相对差异与零附近特殊处理。 |
| F05-R004 | 显示两个模型的独立 provenance 与不同假设，不以“参考”标签掩盖参考模型自身的不确定性。 |
| F05-R005 | 支持共享波长探针、统一 y 轴、锁轴、网格对齐、差异热点定位。 |
| F05-R006 | 汇总多个标准情景的波段偏差，但只有同一有效域的点才参与统计。 |
| F05-R007 | 将比较状态与参考数据 ID 一并导出。 |

**验收**：

- `AT-F05-01`：相同输入下，数值残差与显示/导出结果一致。
- `AT-F05-02`：相对差异在参考值接近零时不产生虚假的极大百分比；使用带阈值的不可用标记及绝对误差。
- `AT-F05-03`：几何或界面条件不一致时不计算“模型偏差”，而是列出不一致项。
- `AT-F05-04`：比较同一模型与完全相同的输入数据得到零差值（浮点容差内），但此操作只作为绘图和计算自检。

**依赖**：F04 参考数据、F01 元数据；此功能不得抢先于独立参考解完成而发布。

### F06｜大气模型对照与非同模大气校正

**用户问题**：大气路径辐射、透射、模型结构与假设误差如何影响水体信号恢复？

**三个实验层级**：`CLOSURE`（原模型配对验证）、`MODEL_MISMATCH`（独立正演/简化反演）、`ERROR_PROPAGATION`（观测与结构扰动）。默认清楚标出实验级别。

| 原子需求 | 必须实现的行为 |
|---|---|
| F06-R001 | 保留 V9 一阶大气公式与其数值闭合测试，但固定名称为教学一阶模式。 |
| F06-R002 | 引入独立来源的大气参考案例；明确是否处理分子—气溶胶耦合、气体吸收、偏振、海面等。 |
| F06-R003 | 增加“真实大气”和“假定大气”两组状态，保留误配增量显示。 |
| F06-R004 | 在支持参考数据的前提下，展示路径反射率、水体贡献、双程透射、校正后 `Rrs` 的分量与残差。 |
| F06-R005 | 明确将气溶胶参数**已知/人为误配**实验和**从 NIR/SWIR/其他波段估计气溶胶**的真正反演分开。 |
| F06-R006 | 对非同模实验增加观测噪声、定标偏差、路径项偏差及水体项模型差异的独立控制或预设。 |
| F06-R007 | 保留负 `Rrs` 作为过校正诊断，不默认裁零；下游算法需要正值时返回明确无效状态。 |
| F06-R008 | 各结果显示 `ideal closure ≠ field validation`；若参考案例没有海气耦合，不得声称完成海洋 TOA 真值模拟。 |

**验收**：

- `AT-F06-01`：完全同模型/同参数时，原模型在既有浮点容差内闭合，并明确标注数值自检。
- `AT-F06-02`：引入规定路径偏差时，恢复 `Rrs` 的符号与代数公式一致。
- `AT-F06-03`：参考模式需验证与独立求解器或参考数据文件一致；无法验证时只显示实验预览。
- `AT-F06-04`：引入负波段时，谱线仍显示原始数值；OC4 等要求正值的算法返回 `invalid_input`。
- `AT-F06-05`：任何海面耀斑/白沫未建模的案例都显示排除标记，不暗示其被消除。

**依赖与风险**：F01、F03；若选用 6SV 或其他大气求解器，必须先审核海面边界、气溶胶高度和水色场景的适用条件。`rho_TOA*` 不可直接冒充真实卫星 TOA 反射率。

## 6. 功能详细规格：F07–F12

### F07｜教学任务引擎与可评价的实验过程

**用户问题**：面对复杂模型，学生如何从定量假设开始，而不是只拖动参数看图？教师怎样判断学生理解的是物理因果，而非界面操作？

**基本交互**：`提出问题 → 预测变化 → 运行/观察 → 解释原因 → 比较/检验 → 记录限制`。实验状态和结论可独立保存。

| 原子需求 | 必须实现的行为 |
|---|---|
| F07-R001 | 提供 LEARN/EXPLORE/VALIDATE 任务入口，三种入口共用同一科学计算结果。 |
| F07-R002 | 每个实验模板写明问题、背景、假设、可调参数、必须观察变量、评价问题及已知模型限制。 |
| F07-R003 | 学生执行实验前可写预测，执行后对照预测与结果，不自动以“相符”判断解释正确。 |
| F07-R004 | 提供指定参数的变量锁定、重置、基线快照和一键 A/B 对照。 |
| F07-R005 | 学生可保存解释文字及导出图表；教师可读取每步模型/数据版本和完整数值状态。 |
| F07-R006 | 设置“解释陷阱”提示，例如：改变太阳角度但基础半解析水体 `Rrs` 不变，不代表真实水体不存在角度依赖。 |
| F07-R007 | 支持本地独立完成；不以必须注册、上传或同步服务器为条件。 |

**首批实验模板**：

| 实验 ID | 核心问题 | 固定条件 | 必须观测 | 最低结论要求 |
|---|---|---|---|---|
| `LESSON-01` | CDOM 与 NAP 对蓝光抑制有何不同？ | 其他 IOP 固定 | `a(λ)` 分量、`Rrs(λ)` | 解释指数斜率而非单看水色 |
| `LESSON-02` | 相近 `u` 能否对应不同组分状态？ | 选择成对 IOP 组 | `a,bb,u,Rrs` | 说明 IOP 反演的非唯一性 |
| `LESSON-03` | 散射相函数如何影响水下角度光场？ | 相同 `a,b` 与照明 | `L(Ω),Ed,Eu` | 说明仅 `bb` 不能完整决定角度场 |
| `LESSON-04` | 大气模型误差在哪些波段更严重？ | 同一水体 | `rho_TOA*`、`Rrs_est`、残差 | 区分路径辐射误差与水体差异 |
| `LESSON-05` | 更多波段一定带来更好反演吗？ | 相同待估参数 | 秩、奇异值、协方差 | 讨论通道相关和模型条件性 |

**验收**：

- `AT-F07-01`：从模板进入实验时，所有设置可追踪且不会与 EXPLORE 结果混用。
- `AT-F07-02`：保存/恢复包含预测、参数、模型 ID、结论和来源。
- `AT-F07-03`：限制无法满足时有可理解的说明，不允许交出“已完成”结果。
- `AT-F07-04`：教师导出的报告能够区分学生填写的解释与计算机生成的结论。

**非目标**：首版不建立复杂 LMS 账号体系或自动判分大模型；如未来增加外部存储，单独进行隐私和权限评审。

### F08｜荧光、非弹性散射及近红外（NIR）扩展

**用户问题**：为什么红边、约 681 nm 荧光敏感区和 700 nm 以上波段不能仅用现有吸收—后向散射关系解释？

**阶段规则**：先补足**未建模标记**；再增加有来源的简化过程；最后才扩展光谱定量有效域。不能把 UI 有波段列表等同于有物理预测能力。

| 原子需求 | 必须实现的行为 |
|---|---|
| F08-R001 | 相关传感器和光谱图标注弹性/非弹性过程的包含状态。 |
| F08-R002 | 增加“仅示意荧光”可选视图时，显式标记 illustration，不并入定量 `Rrs`。 |
| F08-R003 | 定量荧光模块须定义激发、发射、谱形、荧光量子产率假设及辐射量定义。 |
| F08-R004 | 扩展 700 nm 以上水体模型前，更新 `aw/aph/ag/aNAP/bb/β` 所需数据及有效性证据。 |
| F08-R005 | 区分 OLCI 等红边波段对高浑浊/浮游植物信号的敏感性与真正荧光信号。 |
| F08-R006 | 给出模型与观测/参考解的波段检验，错误或缺失时不展示定量预测。 |

**验收**：

- `AT-F08-01`：在未启用新物理模块时，681 nm 结果明确表示“不含荧光贡献”。
- `AT-F08-02`：半解析旧域之外的波长不被旧模型静默计算。
- `AT-F08-03`：实验切换前后，量纲一致且用户可以单独检查弹性/荧光分量。
- `AT-F08-04`：模型新增的每个有效波段都有数据来源、生成脚本与独立验证案例。

**研究约束**：Raman 散射、荧光、底反射可分期独立实现；每新增一项都需要显式源项、边界和测量定义，不可把全部现象合并成任意“补偿谱”。

### F09｜相关误差、数值稳健性与 Monte Carlo

**用户问题**：同一个 Jacobian 在不同误差结构、求导尺度和先验条件下会得到怎样不同的可辨识性结论？

| 原子需求 | 必须实现的行为 |
|---|---|
| F09-R001 | 保留 V9 独立同方差噪声模式作为兼容基线，明确标记 `hypothetical`。 |
| F09-R002 | 新增波段依赖的 `σ_i` 和相关矩阵 `C_ij`，形成 `Σ_ij=σ_iσ_jC_ij`。 |
| F09-R003 | 验证 `Σ` 的对称、半正定/正定性质及数值条件；不可解时给出原因并避免无意义反演。 |
| F09-R004 | 使用稳定的分解方案分析白化、缩放后的 Jacobian（优先 SVD）；保留物理单位导数输出。 |
| F09-R005 | 输出奇异值、数值秩、病态方向、局部条件协方差；满秩不显示“全局唯一”。 |
| F09-R006 | 新增有固定随机种子、可设置样本数的 Monte Carlo；记录误差分布、采样失败、分位数和随机种子。 |
| F09-R007 | 支持不同差分步长或自动稳定性检查；不稳定时提示局部求导不可信。 |
| F09-R008 | 将随机测量误差、定标系统偏差、前向模型结构误差分开统计与标注。 |
| F09-R009 | 长时计算可中止、不覆盖新参数状态下的旧结果；显示执行进度和有效样本数。 |

**输出**：局部信息诊断、Monte Carlo 分布、参数耦合图、条件假设说明、结果状态 (`full_rank`、`rank_deficient`、`unstable_derivative`、`invalid_covariance` 等)。

**验收**：

- `AT-F09-01`：当 `Σ=σ²I` 时，结果与 V9 条件 Fisher 在约定容差内一致。
- `AT-F09-02`：对构造的满秩与秩亏矩阵，秩和奇异值与可信数学基准一致。
- `AT-F09-03`：输入非对称或非正定协方差时必须拒绝或引导修复，不静默求逆。
- `AT-F09-04`：固定实验状态和随机种子，重复 Monte Carlo 输出可复现。
- `AT-F09-05`：改变波段相关性，结果不再错误地沿用旧的独立噪声协方差。
- `AT-F09-06`：用户取消后不得向当前界面回填过期计算结果。

**风险**：采样次数、反演优化迭代和多工作区刷新可能造成主线程阻塞；应采用 Worker、缓存和显式取消。

### F10｜约束多参数非线性反演与非唯一性可视化

**用户问题**：哪些参数组合可以解释同一观测？为什么优化器收敛不等于物理真值唯一？

| 原子需求 | 必须实现的行为 |
|---|---|
| F10-R001 | 定义反演观察向量 `y`、前向算子 `f(p)`、协方差/权重、参数边界和目标函数。 |
| F10-R002 | 至少提供一类可复现的约束非线性最小二乘实现；优化方法及容差应明确。 |
| F10-R003 | 支持多个初始值，展示不同解、收敛轨迹、目标值、约束命中状态。 |
| F10-R004 | 可选择正则化/先验，并标明先验会改变可辨识性及估计不确定性。 |
| F10-R005 | 以独立合成测试集检验算法；避免完全相同数值栅格和完全相同正演误差的逆犯罪。 |
| F10-R006 | 输出拟合谱、残差、最优参数、退出原因、迭代次数与非唯一性证据。 |
| F10-R007 | 处理负波段、无效观测、协方差病态和参数越界；报告数据过滤规则。 |
| F10-R008 | 明确区分前向状态中使用的 `Chl` 与经验 OC4 算法输出的 chlorophyll-a 估计。 |

**建议目标函数**（例，具体优化器由 ADR 决定）：

```text
min_p  [y - f(p)]ᵀ Σ⁻¹ [y - f(p)] + λ ||W(p - p_prior)||²
subject to p_min ≤ p ≤ p_max
```

界面应清楚区分残差最小、满足边界、收敛、可辨识、物理合理与独立验证六种概念。

**验收**：

- `AT-F10-01`：人工构造的单参数解析测试问题能恢复已知解。
- `AT-F10-02`：在非唯一或病态问题中，多个初值可能得到不同参数组合，界面不会仅展示一个“真值”。
- `AT-F10-03`：正则化系数改变时结果和先验信息同步更新。
- `AT-F10-04`：优化失败、达到迭代上限或命中边界时明确展示退出原因。
- `AT-F10-05`：报告可区分拟合优度与外部预测精度。

**非目标**：V10.3 不应直接宣称形成可用于全球水质制图的业务算法。

### F11｜真实数据匹配、质量控制与模型验证

**用户问题**：该模型在独立观测中表现如何？结果是否受观测误差、水型或筛选条件影响？

| 原子需求 | 必须实现的行为 |
|---|---|
| F11-R001 | 导入已审核的标准现场数据集（例如 SeaBASS 资料子集）或带严格模板的本地文件。 |
| F11-R002 | 记录现场测量的时间、经纬度、观测几何、波长、采样方法、单位、数据作者、许可证及质量标志（若原始数据提供）。 |
| F11-R003 | 明确区分现场 `Rrs`、卫星 `Rrs` 和模型 `Rrs`；没有有效匹配关系时不得写“matchup”。 |
| F11-R004 | 对空间、时间、质量、波长匹配采用可配置且可记录的规则；不隐藏筛选样本。 |
| F11-R005 | 输出样本量、有效数、偏差、RMSE、MAE、相关性（满足统计条件时）及分层水型统计。 |
| F11-R006 | 允许按水型、波长、几何、传感器过滤，并显示筛选后样本量。 |
| F11-R007 | 版本化发布数据快照和处理脚本；保留原始出处和法律使用条款。 |
| F11-R008 | 数据来源或质量缺失时，降级为“浏览示例”，而不是计算可发表的模型评价指标。 |

**数据质量最低规则**：重复观测处理、单位换算、异常波段、质量标志、负值处理和日期解析规则必须作为数据集 manifest 的一部分；不可以通过绘图程序悄悄清理数据。

**验收**：

- `AT-F11-01`：使用有精确预期结果的合成验证集，RMSE/偏差/有效样本数正确。
- `AT-F11-02`：改变匹配时间窗或质量标志后，统计和有效样本数同步更新且可复现。
- `AT-F11-03`：缺少授权/来源的外部数据不能发布进生产内置包。
- `AT-F11-04`：测试数据和训练/调参数据有显式拆分；评价报告不能把开发样本称为独立验证。
- `AT-F11-05`：对未匹配的现场与卫星观测，界面不生成无依据的残差解释。

**风险**：真实数据从获取到可发布有较高的清洗、许可、几何匹配和专业审核成本。应先做少量可信标注案例，而不是盲目扩大样本库。

## 7. 技术架构与科学数据接口

### 7.1 架构总览

```text
                       UI / ROUTER / LESSON RUNNER
                                  │
                                  ▼
                        EXPERIMENT STATE STORE
                                  │
                                  ▼
                          SCIENCE MODEL GATEWAY
                                  │
                 ┌────────────────┼──────────────────┐
                 │                │                  │
                 ▼                ▼                  ▼
          SEMI-ANALYTICAL    REFERENCE RT       OBSERVATION
          V9-compatible     offline snapshots   field/matchups
                 │                │                  │
                 └────────────────┼──────────────────┘
                                  ▼
                         QUANTITY + PROVENANCE
                                  │
                 ┌────────────────┼──────────────────┐
                 ▼                ▼                  ▼
            ATMOSPHERE         SENSOR             VALIDATION
            + CORRECTION      + SRF                + COMPARE
                 │                │                  │
                 └────────────────┼──────────────────┘
                                  ▼

```

核心原则：**一个物理引擎，多种视图**。不得为教学页、自由探索页和验证页复制三份计算代码。每个模型以统一接口输入输出；所有科研对象必须可序列化、可审核。

### 7.2 推荐的源代码结构（规划目标）

### 7.3 模型 Adapter 最低接口

```ts
// 类型示意，正式接口由 ADR 和 TS/JSON Schema 文件冻结。
type QualityStatus =
  | 'valid' | 'partial' | 'out_of_domain'
  | 'missing_data' | 'failed' | 'not_applicable';

type Quantity = {
  name: string;                   // e.g. Rrs, Ed, Lu
  units: string;                  // e.g. sr^-1, W m^-2 nm^-1
  axes: { name: string; unit: string; values: number[] }[];
  values: number[] | number[][] | number[][][] | null;
  status: QualityStatus;
  reason?: string;
  assumptions: string[];
  uncertainty?: { value: unknown; kind: string };
};

type ModelResult = {
  modelId: string;
  modelVersion: string;
  modelType: 'SEMI_ANALYTICAL' | 'REFERENCE_RT' | 'OBSERVATION' | 'SIMULATED_OBSERVATION';
  inputs: Record<string, unknown>;
  quantities: Record<string, Quantity>;
  provenance: Record<string, unknown>;
  warnings: string[];
};
```

**接口不变量**：

1. `status != valid` 时必须声明原因；禁止从 `null` 自动转成 0。
2. 输出数组形状必须与轴定义匹配；维度不合时拒绝渲染为科学数据。
3. 各派生量只能由声明的原始变量计算；例如 `Kd` 的导数定义须与深度网格一致。
4. 可变换单位须明确转换；不允许在前端标签中直接替换单位字符。
5. 插值值必须携带 `interpolated=true`、插值方法和适用性；模型外插默认为禁止。
6. `modelType=OBSERVATION` 仅用于真实观测数据对象；带噪声合成结果必须使用 `SIMULATED_OBSERVATION`。

### 7.4 参考 RT 数据包最低 manifest

| 字段 | 内容与要求 |
|---|---|
| `referenceId` | 稳定唯一 ID |
| `solver` | 名称、版本、构建选项、来源 URL |
| `method` | 求解方法、角度/深度/波长离散化 |
| `physicalInputs` | `a, b, β/P`、界面条件、光源及几何 |
| `coordinateConvention` | `z` 正方向、极角方位、参考面 |
| `axes` | 波长、深度、方向数组及单位 |
| `quantities` | `L,Ed,Eu,Lu,Kd,Rrs` 的实际覆盖，不支持须显式声明 |
| `numericalAccuracy` | 网格收敛、求解容差、对照误差 |
| `validity` | 参数/波长/角度适用域和是否允许插值 |
| `provenance` | 生成脚本 commit、输入快照、UTC 时间、哈希 |
| `license` | 原始数据/模型许可证和再分发许可 |

若参考求解器不能合法地随网站分发，允许离线生成经过许可的派生数据；这必须在数据使用记录中说明。禁止为了方便忽略 GPL 或机构数据的独立分发条件。

### 7.5 数值策略与执行调度

| 任务 | 推荐策略 | 科学限制 |
|---|---|---|
| V9 半解析模型 | 主线程即时计算，可缓存 | 不伪装为角度 RT |
| RT 参考案例 | 静态压缩分块数据 + 按需加载 | 严格限定网格及插值域 |
| 参考案例插值 | 明确的有界插值算法 | 未验证的高维外插禁用 |
| 误差矩阵分解 | Worker / 可信数值库 | 记录精度、阈值及失败条件 |
| Monte Carlo | Worker + 可固定 seed | 显示有效样本和取消状态 |
| 非线性反演 | Worker + 可停止迭代 | 收敛≠唯一≠真实准确 |
| 现场数据验证 | 分块加载 + 质量过滤 | 必须保留原始数据及处理链 |

**并发规则**：每次实验参数改变都生成新 `runId`。异步结果携带同一 `runId` 才能写入当前界面；已取消或过期结果不得污染状态。科学计算缓存键至少包含模型版本、参数、数据版本、谱/角网格和有效性选项。

## 8. 非功能需求（NFR）与交互质量门槛

| ID | 要求 | 具体验收方式 |
|---|---|---|
| NFR-01 | 科学复现 | 固定输入/随机种子/数据与模型版本可重复生成同结果；数值容差写入测试 |
| NFR-02 | 模型隔离 | V10 数值代码不能静默覆盖 V9 原始代码或迁移历史结果 |
| NFR-03 | 响应能力 | 普通半解析参数滑动无明显阻塞；以目标设备上的 p95 实测值写入性能基线 |
| NFR-04 | 长任务可取消 | RT 数据加载、MC、反演具有进度/取消/过期结果处理 |
| NFR-05 | 图表一致性 | 同一变量统一单位、色标、轴方向；默认提供锁轴及残差方式 |
| NFR-06 | 响应式 | 桌面/平板/移动端主要工作区均可操作；无不可恢复的遮挡 |
| NFR-07 | 可访问性 | 键盘导航、可读的图表数据表、焦点管理、图表颜色不单独承载关键信息 |
| NFR-08 | 离线/弱网 | 已缓存的模型和教学案例可用；缺数据时清晰降级，不报假值 |
| NFR-09 | 数据安全 | JSON/CSV 导入严格校验；无脚本执行、无任意远程资源注入 |
| NFR-10 | 隐私 | 教学输入与实验笔记默认本地保存；上传需明确授权和隐私说明 |
| NFR-11 | 国际化 | 科学符号与单位不因中英文切换改变；文本翻译不会修改模型数据 |
| NFR-12 | 代码质量 | 模型单测、集成测、浏览器测及科学审查都作为 CI 门槛 |
| NFR-13 | 数据治理 | 内置数据包保留来源、许可、生成脚本和 checksum |
| NFR-14 | 部署回滚 | 新引擎失败时有明确回退信息；不得无声从 V10 回退 V9 并保留 V10 标签 |
| NFR-15 | 性能预算 | 下载体积、内存、首帧、计算延迟在第一个性能基线版本确定并持续监控 |

**性能预算说明**：目前没有基准设备的实测数据，因此不应把例如“200 ms”“10 MB”直接声明为已证实的硬门槛。V10.0 应建立基线设备/浏览器矩阵，并由产品与技术负责人批准明确阈值。科学计算精度优先于伪造的即时交互。

### 8.1 图表与可视化专项规范

- 同轴 A/B 比较默认保持相同纵轴；自动 Y 缩放必须醒目标记，提供锁轴按钮。
- 光谱颜色仅作视觉识别，不作为定量“真实海色”声明；若渲染可见颜色，记录显示器/色度转换假设。
- 角度图注明“方向辐亮度”或“对若干角度采样的插值”，不可写成单纯“光强”。
- 浓度、吸收、后向散射、辐亮度、辐照度、反射率不能因数量级近似而共用无量纲纵轴。
- 当残差相对参考值接近零时，优先显示绝对残差并解释百分比不可用。
- 每张图至少提供：标题、量/单位、模型标签、有效数据范围、数据探针、导出入口。
- 深度图显示正方向和水面；相函数图显示散射角定义和归一化说明。
- 缺测/不适用值应使用断裂、占位或灰区，不用插值线穿越不可用区域。

### 9.2 科学标准案例目录建议

| Case ID | 输入类别 | 要验证的机制 | 必须输出 |
|---|---|---|---|
| `CASE-SA-CLEAR` | V9 清澈海水基线 | 旧半解析回归 | `a,bb,rrs,Rrs` 全谱 |
| `CASE-SA-CDOM` | CDOM 丰富 | 参数化谱形和蓝光响应 | 分量与全谱 |
| `CASE-SA-PARTICLE` | 颗粒丰富 | 吸收/后向散射关系 | 分量与全谱 |
| `CASE-RT-CLEAR-A` | 清澈海水 RT | 深度衰减和方向性 | `L,Ed,Eu`、边界量 |
| `CASE-RT-PHASE-B` | 等价 `a,b` 不同相函数 | 方向性对照 | 角度分布和 `Rrs` |
| `CASE-RT-GEOM-C` | 固定 IOP、不同太阳角 | 几何影响 | 角度/光谱对照 |
| `CASE-ATM-CLOSURE` | 同一前向/反演模型 | 数值闭合 | TOA、恢复 `Rrs` |
| `CASE-ATM-MISMATCH` | 独立参考+简化校正 | 结构性残差 | 偏差与波段分量 |
| `CASE-SRF-CONSTANT` | 常数谱 | SRF 归一化 | 正确带平均 |
| `CASE-SRF-PARTIAL` | 不足波段覆盖 | 缺测规则 | `partial/out_of_domain` |
| `CASE-UNC-RANKDEF` | 退化 Jacobian | 局部秩诊断 | `rank_deficient` |
| `CASE-UNC-CORR` | 相关观测误差 | 广义协方差 | 标准数学基准一致 |
| `CASE-INVERSE-MULTI` | 多解/病态合成问题 | 反演非唯一性 | 多初值解与状态 |
| `CASE-FIELD-MOCK` | 人工统计验证集 | 数据统计与过滤 | 正确样本量和 RMSE |

**每个案例需配套**：固定输入、预期输出或可验证性质、求解器/数据来源、哈希、容差、测试脚本、失效时的定位说明。无法给出精确真值的案例，应报告独立收敛证据和比较误差，不得编造“真值”。

### 9.3 容差制度

不同类别不能使用一个通用浮点误差阈值。

- **数学恒等式**：使用相对与绝对容差，阈值以 IEEE 精度和条件数为依据。
- **V9 回归**：比较相同模型、系数和源数据；要求逐波长一致或在批准的舍入容差内一致。
- **独立 RT**：阈值随波长/角度/深度、模型近似和网格收敛报告确定；绝不能预先拍脑袋写固定“1% 科学精度”。
- **实测验证**：RMSE 等属于数据样本统计，不是程序浮点测试；必须标注样本量和独立性。
- **不确定性分布**：Monte Carlo 的随机波动与确定性数值回归分别测试；固定随机种子只是复现保证，不是统计正确性证明。

### 9.4 发布 Gate

| Gate | 必须通过 | 允许的发布级别 |
|---|---|---|
| G0 科学语义 | SC 合同、单位、有效性标志、来源审核 | 任何公开版本 |
| G1 软件回归 | T0/T1/T2/T4/T5，无阻断缺陷 | 正式产品功能 |
| G2 RT 可信 | 独立 RT 参考、输入一致、收敛及参考对照 | 可以使用 `REFERENCE_RT` 标签 |
| G3 反演可信 | 偏差/噪声/先验隔离；非同模测试与异常处理 | 可以使用“反演实验” |
| G4 观测验证 | 数据授权、独立匹配、质量过滤、统计与来源 | 可以使用“观测验证” |
| G5 可复现 | 导出/导入、科学数据 checksum、模型版本和原始参考记录 | 可以宣称“实验可复现” |

**禁止性发布用语**：未过 G2 不得称“真实 RT 求解”；未过 G3 不得称“可靠反演”；未过 G4 不得称“经真实观测验证”；未进行任务特定验证，不得统称“科研级精度”。

## 10. 分版本实施计划与交付边界

### 10.1 V10.0｜科学一致性与可维护底座

**版本目标**：不更换 V9 的科学基线，先统一数据定义、错误处理、模型身份、SRF/反演输入与导出兼容性。此版本还**不能**宣称已经具备完整水下 RT。

| 需求 | 纳入范围 | 交付物 | 出口条件 |
|---|---|---|---|
| F01 | R001–R007 | 模型契约、变量字典、有效性面板 | G0、G1 |
| F02 | R001–R003、R007 | 参数化基线保留与 CDOM/NAP 斜率教学切换 | 旧谱回归 |
| F03 | R001–R007 中的可交付基础项 | SRF 标准化、带积分与 OC4 输入路径清晰标记 | `AT-F03-*` 相关通过 |
| F12 | R001–R004、R008 | schema 规划/实现、旧实验迁移、安全导入 | G5 的核心部分 |
| NFR | 版本与性能基线 | 目标设备矩阵、CI、错误日志定义 | 无阻断问题 |

**最小用户可见变化**：在每条科学曲线旁看到模型身份；从传感器波段中区分中心取值与积分值；数据缺失可明确解释；旧实验仍可打开。

**首版不做**：通用 RT 实时求解、真实卫星产品、荧光定量、现场匹配、大规模 Monte Carlo。

**版本退出评审问题**：

1. 是否还有以“显示了数值”冒充“数值有效”的入口？
2. 是否所有科学变量都能追溯模型版本及单位？
3. 从 V9 导入的实验是否保留原始数值语义？
4. 新增的 OC4/SRF 路径是否没有破坏旧教学模式？

### 10.2 V10.1｜独立 RT 参考与同条件模型对照

**版本目标**：交付首个真正增加辐射传输教学深度的核心功能。

| 需求 | 纳入范围 | 交付物 | 出口条件 |
|---|---|---|---|
| F04 | R001–R010 的最小可发布实现 | WATER RT、三种水体案例、深度/角度光场 | G2 |
| F05 | R001–R007 | 半解析/RT 同条件曲线与残差 | G2、G5 |
| F12 | R005–R007 扩展 | 参考数据/求解器记录、对照导出 | 可复算 |
| F07 | 最小实验草案 | 至少一个指导式 RT 任务内部预览 | 未达验收则继续实验性标记 |

**首发能力冻结建议**：三种水体案例；受限的照明/相函数设置；`L` 方向分布、`Ed/Eu` 深度剖面和 `Rrs` 模型比较；共享波长探针；完整来源导出。

**必要前置决策**：RT 求解器选择（ADR）、边界条件、角度深度离散策略、可下载参考数据版权。**任一项未审定时，V10.1 不得发布为正式 WATER RT。**

| 需求 | 纳入范围 | 交付物 | 出口条件 |

| F06 | R001–R008 的可验证标准案例 | 三层大气校正实验 | G3 |
| F07 | R001–R007 | 至少三个完整 LEARN 实验 | 教学验收 |

**可检验的重点结果**：同模型闭合的残差接近数值零；当生成数据与反演模型不一致时出现可解释残差；报告明确区分学生推断与软件计算。

### 10.4 V10.3｜不确定性、反演与观测验证

**版本目标**：从模型比较扩展到条件误差、反演非唯一性、独立观测评价。

| 需求 | 纳入范围 | 交付物 | 出口条件 |

### 10.5 更远版本（V11+）的准入条件

只有满足以下条件之一，才进入下一代主版本规划：

- 推出经过独立验证、具备显式多次散射与广角度可计算能力的新 RT 内核。
- 实现具有足够数据覆盖、可审查误差、已获许可的广域水体/大气案例库。
- 集成新的物理边界（如浅水底反射、完整荧光和拉曼过程），并改变主要科学使用场景。
- 开始面向业务或科研反演报告输出，同时建立正式的性能评估与质量保证程序。

单纯 UI 改版、增加传感器列表或新增实验教学卡片不应触发主版本升级。

### 12.1 资源成本拆分

估算成本时须分开以下工作，而不能仅按前端页面数量估算：

1. 科学研究与资料审核：参数化源、RT 求解器、输入有效域、观测许可。
2. 离线数据生产：RT 场景网格、计算资源、收敛测试、压缩格式。
3. 模型与数值实现：接口抽象、插值、误差矩阵、反演稳定性。
4. 交互与教学设计：统一图表、过程动画、课程卡片、移动端。
5. 质量与维护：自动测试、基准更新、数据和算法版本管理。
6. 真实数据工作：数据清洗、时空匹配、质量标志与法律审查。

**估算原则**：在明确参考模型和目标场景数量前，不提供未经支持的总开发工期或人工成本。每个版本的成本评估表应列：人天区间、科研评审人天、计算资源、数据许可费用、回归测试和长期运维成本。

## 13. 版本治理、迁移和回滚制度

### 13.1 版本号分离

不要只用 UI 版本号代替科学版本。建议同时记录：

| 版本字段 | 改变条件 | 示例 |
|---|---|---|
| `appVersion` | UI、交互、部署变化 | `10.1.0` |
| `scienceModelVersion` | 公式、参数化、边界条件变化 | `SA-V9.1-compat` 或新的审定 ID |
| `referenceDataVersion` | RT/SRF/验证数据集改变 | `RT-Cases-1.0` |
| `experimentSchemaVersion` | JSON 数据结构变化 | `7`（拟议） |
| `algorithmVersion` | Jacobian/反演/统计方法变化 | `uncertainty-2.0` |
| `releaseToken` | 静态资源缓存更新 | 独立构建/部署标识 |

发布时必须提供上述版本组合。引用旧实验时，应优先使用实验自身版本，而不是当前页面默认版本。

### 13.2 科学变更类型

- **类型 A：表示修订**。仅改善文案/布局，科学结果不变；保留科学模型版本。
- **类型 B：数值等价重构**。公式语义不变，允许在审定容差内产生数值差异；需要黄金测试。
- **类型 C：模型修正/扩展**。参数化、求解、有效域、边界条件改变；必须新科学模型版本及 ADR。
- **类型 D：数据更新**。同公式但 SRF/系数/参考数据变化；新数据版本及来源记录。
- **类型 E：统计解释更新**。误差模型、优化准则、质量筛选改变；新算法版本并标记历史不可直接比较的部分。

### 13.3 实验迁移策略

```text
读取实验文件
     │
     ▼
检查 schema / 长度 / 类型 / 来源
     │
     ├── 无效 ──► 拒绝并给出诊断
     │
     ▼
识别旧版本（v3/v4/v5/v6/...）
     │
     ▼
显式迁移并标记未知元数据
     │
     ├── 科学模型缺失 ──► 仅打开历史快照 / 提示限制
     │
     ▼
保留历史计算结果 + 可选在新模型下重算
     │
     ▼
若重算则生成新的派生记录，不覆盖原始记录
```

**特别要求**：任何历史模型结果不得在导入后被新默认模型静默替代。重算结果和旧结果具有不同科学签名，并可展示差异。

### 13.4 上线与回滚

- 新模块先在开发/预览路由验证；主站默认只启用达到 Gate 的功能。
- 切换 `site/core/modules.js` 的版本入口之前，确认静态资源、缓存 token、iframe 启动/错误处理、实验迁移与回滚路径。
- V10 启动失败时允许回退 V9，但必须明确展示“V9 fallback”，并停用所有 V10 专属科学结论。
- 构建/导出应记录 Git commit 和数据源校验和；任何回滚不能删除现有实验文件。
- 已经正式发布的模型若发现重大物理错误，应发布已知问题公告、修正模型版本、标注影响范围并附重算指导。

## 15. 待澄清但不应阻断起步的研究问题

本节问题不应由开发人员私自猜测，需在对应 ADR/科学评审中解决。

1. **参考水体 RT 用什么求解器？** 需要对角度、深度、边界、非弹性源项及许可逐项比较。
2. **RT 参考解针对什么水型？** 清澈海洋、富藻海水和高颗粒水体的参数必须可追溯，而不是视觉预设。
3. **不同散射相函数如何参数化？** 必须能从相函数计算一致的 `b` 和 `bb`；需决定体积散射函数来源。
4. **海气界面如何衔接？** 半解析 `rrs→Rrs` 近似与 RT 显式边界不能未经转换直接比较。
5. **大气参考解是否包含海面反射和偏振？** 未包含的效应必须单独保留排除声明。
6. **OCI/OLCI 官方响应曲线选哪个版本？** 需区分平台、探测器、随时间变化和再分发许可。
7. **何时可以定量扩展到 700 nm 之外？** 不能只增加光谱数组长度，而应重新验证 IOP/AOP 和非弹性机制。
8. **高相关误差如何构造？** 教学模拟可以有可控矩阵，但不得标为某传感器真实规格。
9. **验证数据是否具有独立性？** 参数拟合数据、教学例子和测试集合不能被混为一类。
10. **怎样保证长期维护？** 需确定开发、人力审核、数据存储和持续校准的实际预算。

## 附录 A｜专业术语统一表

| 符号/术语 | 标准含义 | 单位/说明 |
|---|---|---|
| IOP | 固有光学特性 | 不依赖外部照明场 |
| AOP | 表观光学特性 | 依赖光场与几何 |
| `a` | 吸收系数 | `m⁻¹` |
| `b` | 总散射系数 | `m⁻¹` |
| `bb` | 后向散射系数 | `m⁻¹`，不是 `b` |
| `β` / VSF | 体积散射函数 | 按求解器归一化约定，常用 `m⁻¹ sr⁻¹` |
| `L` | 辐亮度 | 按光谱变量给出 `W m⁻² sr⁻¹ nm⁻¹` 等 |
| `Ed` / `Eu` | 下行/上行平面辐照度 | 按光谱变量给出 `W m⁻² nm⁻¹` 等 |
| `Lu` | 指定向上观测方向的辐亮度 | 光谱辐亮度单位 |
| `rrs` | 刚好水面下遥感反射率 | `sr⁻¹` |
| `Rrs` | 刚好水面上遥感反射率 | `sr⁻¹` |
| `rho` | 反射率或反射率因子 | 一般无量纲，**必须声明约定** |
| `Kd` | 下行辐照度漫衰减系数 | `m⁻¹`；定义及深度范围需明确 |
| SRF/RSR | 光谱响应函数/相对光谱响应 | 权重通常无量纲，依数据规范 |
| `L_TOA` | 大气顶辐亮度 | 辐亮度单位 |
| `rho_TOA*` | 本项目简化大气顶反射率 | 无量纲；`*` 表示教学近似 |
| Jacobian | 参数对观测的局部导数矩阵 | 每列单位随参数变化 |
| Fisher | 条件信息矩阵 | 取决于误差/模型假设 |
| 数值秩 | 指定阈值下的局部矩阵秩 | 不等于全局唯一性 |
| 逆犯罪 | 同模生成/反演导致的自一致性假象 | 不能作为独立精度验证 |
| Matchup | 按明确时间、空间、光谱与质量规则形成的匹配样本 | 不是任意两条曲线并列 |
